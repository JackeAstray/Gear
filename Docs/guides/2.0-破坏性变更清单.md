# 2.0 破坏性变更清单

> 面向维护者。这份清单里的改动都会**破坏接入方编译**或改变公开 API 语义，因此不随 1.3.x 发布，
> 统一在 2.0 做一次。1.3.1 已经把「必须现在修」的部分（加密帧防重放、`Modules.All` 只读）做完，
> 剩下的是**一致性**问题：不改也能跑，但和 .NET / Unity 的命名惯例不一致，长期会持续误导读者。
>
> 执行原则：**一次做完、一个提交、同步 Tests / 文档 / 示例**。半途而废比不改更糟。

## 1. 公开成员改 PascalCase

| 位置 | 现状 | 目标 | 影响 |
|---|---|---|---|
| 14 个系统的初始化标志 | `public bool isInited { get; private set; }` | `IsInited` | `ICustomSystem` 实现与所有调用点 |
| `HttpResponse` | `url` / `isSuccessful` / `isHttpError` / `isNetworkError` / `statusCode` / `bytes` / `text` / `error` / `texture` / `responseHeaders` | `Url` / `IsSuccessful` / … | HTTP/DownLoad 全部调用点 + 示例 |
| `Timer` | `duration` / `elapsed` / `isRunning` / `isPaused` 等 | `Duration` / `Elapsed` / `IsRunning` / `IsPaused` | `TimerMgr`、暂停/存档逻辑、用例 |

为什么当初是 camelCase：这些类照着 Unity 序列化字段的习惯写（`[SerializeField] private int x` 暴露成 MiniGetter），
但**它们不是序列化字段**，而是普通 C# 属性 —— 沿用 Unity 的 camelCase 只会让调用方以为在写 Unity API。

执行命令（示例，逐个类型替换后再全局搜残留）：

```powershell
# 先看影响面
grep -rn "\.isInited\b" --include=*.cs Unity/Gear/Assets/Gear | Measure-Object -Line
# 改名后确认无残留
grep -rn "\bisInited\b" --include=*.cs Unity/Gear/Assets/Gear
```

## 2. 接口改名

| 现状 | 目标 | 说明 |
|---|---|---|
| `public interface UIImgComponent`（文件 `UIImgComponent.cs`） | `IUIImageComponent`（文件 `IUIImageComponent.cs`） | .NET 约定：接口 `I` + PascalCase；`Image` 不要缩写 |

同类待查：仓库里 34/35 个接口已符合 `I` 前缀，剩下的就是这一个。

## 3. 文件名与主类型不一致

**已在本轮完成（`git mv`，类型名不变，不影响编译）**：

- `KCPClientChannel.cs` → `KcpClientChannel.cs`（类型 `KcpClientChannel`）
- `KCPServerChannel.cs` → `KcpServerChannel.cs`（类型 `KcpServerChannel`）
- `VertexStream.cs` → `VertexDataStream.cs`（类型 `VertexDataStream`）
- `UIWindowResult.cs` → `WindowResult.cs`（类型 `WindowResult<T>`）

**仍待处理**（改名会影响读者定位，需要同一次提交里同步文档与工具箱）：

| 文件 | 内含类型 | 建议 |
|---|---|---|
| `Framework/Modules/Download/Utils/CommonExtensions.cs` | `Extensions` | 改 `Extensions.cs`；若担心同名冲突，改 `StringArrayExtensions.cs` |
| `Utilities/UI/ImageExtensions/Runtime/Common/Type.cs` | `DrawShape` / `GradientType` / `MaterialMode` / `CornerStyleType` | 一个文件塞 4 个枚举，改 `ImageExEnums.cs` 并考虑拆成 4 个文件 |

## 4. 命名空间 / 程序集对齐

| 项 | 现状 | 目标 |
|---|---|---|
| `Gear.Base` | asmdef `rootNamespace` 为空，文件里手写命名空间 | 统一 `Gear.Base`，文件用 `namespace Gear.Base` |
| `CoreEnum.cs`（`Common/Enum/`） | 类型落在 `Gear.Framework.Runtime` 命名空间但物理在 `Common/` | 移到 `Gear.Common`（或把文件挪进 `Framework/Runtime`） |
| `TreeView/`（`Utilities/UI/TreeView/`） | `namespace Gear` | `Gear.Utilities.UI.TreeView` |
| `ButtonClickEvent.cs` | `Gear.Utilities.UI.ButtonClick` | `Gear.Utilities.UI`（与同目录 `ButtonExtensions` 系列一致） |
| 全局命名空间类 | 少量工具类没有命名空间 | 全部收进对应程序集的命名空间 |
| `Config.Enable_LOG` | 下划线命名 | `EnableLog`（连带 `Log.IsEnabled` 的读取处） |

## 5. 执行顺序（建议）

1. 先做 §3 剩余两个文件改名（纯 `git mv`，零编译影响）。
2. 再做 §2 接口改名（单文件 + 引用点，影响面小）。
3. 最后做 §1 + §4（机械但波及面大，用 IDE 的 Rename Symbol 一次改完，别用 sed）。
4. 每步跑：`dotnet run --project Tools/SyntaxCheck -- Unity/Gear/Assets/Gear` →
   `powershell -File Tools/unity-verify.ps1 -UnityPath <Unity>`（EditMode + 守卫 + PlayMode）。
5. 步骤 3 会动示例与文档，同步更新 `Docs/03-新增一个窗口.md`、`Docs/02-新增一个系统.md` 里的代码片段，
   跑 `dotnet run --project Tools/DocsCheck -- .` 确认链接不碎。

## 6. 破坏性变更怎么发布

- `CHANGELOG.md` 开 `## [2.0.0]` 段，按 "Breaking / Added / Fixed" 分组，**逐条写迁移方式**（不是只写"改名了"）。
- 包版本走 `GearUpmExporter.PackageVersion` → `2.0.0`，`README.md` / `Docs/Packaging/UPM打包指南.md` 同步。
- 给接入方提供一页迁移对照表（旧名 → 新名），放在 `Docs/guides/` 下。
- 1.3.x 分支保留维护，只修安全问题，不再接受新特性。
